Project switcher + status normalization

Two small changes that propagate across the entire app with no new pages.

1. Global project switcher

Scope pill in the top bar — persists across every list and detail page. Per-page "Project" dropdowns get removed.

Before
SC Dashboard · Projects · Domains · Servers · Repos · ... D
/servers
📁 Project ▼ Tag: env=prod × Apply
↓ User goes to /domains...
/domains
📁 Project ▼ (scope is lost — user must re-select)
After
SC production▼ Dashboard · Projects · Domains · Servers · Repos · ... D
/servers?project=prod
Tag: env=web × Status: at-risk ×
↓ User navigates to /domains — scope is kept
/domains?project=prod
Scope preserved: production

Behavior

  • Clicking the project chip opens a dropdown: production, staging, customer-foo, All projects, + New project.
  • Selection is stored in the URL (?project=prod) → shareable, deep-linkable, survives page reload.
  • Every list page (Servers / Domains / Repos / Findings) implicitly filters by this scope; no per-page project dropdown needed.
  • "All projects" is the default for admins; individual projects are opt-in scopes.

2. Status & color normalization

Three parallel vocabularies today collapse into three dimensions with consistent language.

Before — vocabularies clash
Servers
online warning critical offline dead
Domains
healthy degraded down pending
Findings
open in_progress resolved ignored
A red chip could mean: "the server is in critical state", "the domain is unreachable", or "there's an open critical finding". User has to context-switch to know.
After — 3 orthogonal dimensions
Health · applies to every asset
healthy at-risk critical unknown
Operational state · is the asset reachable?
● up ○ down
Work state · findings, invitations (task lifecycle)
○ new in-progress resolved ✕ dismissed
Same words, same colors, same meaning — regardless of whether you're looking at a server, domain, repo, or finding.

Migration mapping

How existing labels map to the new vocabulary. Storage stays the same — only the display layer changes.

Current label Asset type → New label Dimension
onlineServer → healthy + ● up Health + Op
warningServer → at-risk + ● up Health + Op
criticalServer → critical + ● up Health + Op
offline / deadServer → unknown + ○ down Health + Op
healthyDomain → healthy + ● up Health + Op
degradedDomain → at-risk + ● up Health + Op
downDomain → critical + ○ down Health + Op
openFinding → ○ new Work
in_progressFinding → in-progress Work
ignoredFinding → ✕ dismissed (with reason) Work

💡 Why this is the cheapest win

  • One shared design-system token for health/op/work state → every chip in the app uses the same palette and wording.
  • No data migration needed — the mapping lives in a frontend display helper. Backend labels can stay unchanged or be renamed incrementally.
  • Project switcher is one top-nav change + one URL-state hook + 3 list-page cleanups. ~1 day.
  • Makes Options A and B feel right — those redesigns lose impact if the terminology underneath is still inconsistent.
  • Backward compatible — existing filter URLs keep working; the switcher is additive.
